<p>搜「住宅 IP 代理排名」，出来的榜单大多按谁给的钱多排。真正能拿来下决策的，是把「排名」拆成参数：延迟分位、可用率、抖动、单 IP 连接上限、替换政策、工单响应。每个参数都有明确的定义、单位和测法，填满这张表，排名自然就出来了，不必依赖别人的口径。这篇按说明书的方式写，逐项给出定义与合格线，方便你拿自己的数据去填。</p>

<h2>一、把「排名」翻译成六个可测参数</h2>
<p>榜单的问题不在结论，而在不可复现。同一家供应商，在别人的网络环境里延迟 120 毫秒，在你这里可能 300 毫秒。参数化的意义就是把不可复现的结论，换成可以自己测、可以写进合同的数字。</p>

<h3>六个参数分两组</h3>
<p>质量组三个：延迟分位、可用率、抖动。能力组三个：单 IP 连接上限、并发口径、替换政策。前者决定用起来顺不顺，后者决定出问题时能不能兜住。</p>

<h3>每个参数都要写单位和测法</h3>
<p>没有单位就没有意义。「延迟低」不是参数，「P95 首字节 240 毫秒，采样 200 次，晚高峰 20:00 至 22:00」才是。合同附件里也可以这么写，日后争议时有据可依。</p>

<h2>二、延迟：看 P95 与抖动，平均值会骗人</h2>
<p>平均值是最没用的指标。一条线路上午 80 毫秒、晚上 600 毫秒，平均下来三百多，看起来还行，实际晚高峰根本没法用。要看得是分位数：P50 代表常态，P95 代表你能忍到哪，P99 代表最坏情况。</p>
<img src="/tp.png" alt="延迟测试结果分布图展示P50、P95与晚高峰抖动范围">
<p>采样要覆盖时段。至少取工作日白天、晚高峰 20:00 至 22:00、周末各一段，每段不少于 100 次请求。工具上 curl 的 -w 参数就能输出分段耗时，写个循环跑一轮即可，不必上专业压测平台。</p>

<h3>分段耗时比总耗时有用</h3>
<p>把一次请求拆成 DNS、TCP 握手、TLS 握手、首字节、传输五段，能看出瓶颈在哪一段。DNS 段特别长通常意味着没走远程解析；握手长通常是线路绕路；首字节长可能是出口到目标之间的问题。</p>

<h3>抖动大说明线路不稳</h3>
<p>抖动超过 150 毫秒时，体感是「忽快忽慢」，比稳定的高延迟更难受。抖动大的线路往往共享带宽争抢严重，这类线即使 P50 好看，也不适合长期挂账号。</p>

<h2>三、可用率：分母写清楚才有意义</h2>
<p>供应商说可用率 99.9%，先问分母是什么。是按分钟采样、按请求采样，还是按小时采样？按小时采样时，一小时里挂 50 分钟也算这一小时不可用，数字会很难看；按分钟采样时，零星丢包会被摊薄。</p>

<h3>自己怎么测</h3>
<p>每分钟发一次轻量请求，记录成功与失败，连续跑七天。这个频率对出口压力可以忽略，但足以反映真实可用性。失败要区分类型：连接失败、超时、返回错误码，三类的严重程度不同。</p>

<h3>可用率和延迟要一起看</h3>
<p>一条线可用率 99%，但每次成功都要等五秒，实际体验远差于可用率 97%、延迟 200 毫秒的线。把两个参数画在同一张图上，才能看出哪条线是「能用」而不是「能连上」。</p>

<h2>四、售后响应：工单时长与替换政策怎么量化</h2>
<p>售后是最容易被忽略的参数，因为它平时不产生价值，出事时决定损失大小。量化的方法是看两个数：首次响应时长、问题解决时长，再加一条替换政策。</p>

<h3>首次响应与解决时长</h3>
<p>首次响应指提交工单到有人回复的时间，解决时长指到问题闭环。行业里首次响应从几分钟到几小时都有，跨时区的供应商夜间会更慢。买之前可以提交一个非紧急问题试一下，比看宣传页可靠。</p>

<h3>替换政策的三个细节</h3>
<p>免费次数、生效时效、是否需要举证。有的供应商要求提供截图和 traceroute 才给换，流程走完可能一两天；有的后台一键换，几分钟生效。对长期账号来说，后者价值更高。</p>

<h2>五、参数之外的两个否决项</h2>
<p>有些问题不是参数能表达的，但一旦出现就直接排除。第一条是计费口径含糊，第二条是节点信息不透明。</p>

<h3>计费口径含糊</h3>
<p>问「超流量怎么算」「并发超限是排队还是拒绝」「中途降配怎么处理」，如果回答是「看情况」「到时候再说」，后面大概率会有争议。这类供应商即使参数好看，也不适合长期合作。</p>

<h3>节点信息不透明</h3>
<p>正规服务商会明确标注出口所在城市、ASN 类型、是否独享。只写「美国住宅」而不说城市和运营商的，实际拿到的可能是转售的共享池。信息透明本身就是一种质量信号。</p>

<h3>填表之后的用法</h3>
<p>六到八个参数填完，按权重打分。长期账号场景把可用率和替换政策权重调高，短期任务把延迟和计费灵活度调高。权重不同，排名就不同，这恰恰说明「统一排名」这件事本身不成立。</p>

<h2>常见问答</h2>
<h3>延迟多少算合格？</h3>
<p>答：看出口地区。亚洲出口首字节 P95 在 300 毫秒以内体验较好，欧美出口 500 毫秒以内可接受。跨洲访问天然有物理延迟，低于 200 毫秒的报价要多留个心眼，可能测的是就近节点。</p>

<h3>可用率 99.9% 可信吗？</h3>
<p>答：先问采样口径。按分钟采样、按请求采样、按小时采样，结果差别很大。自己跑七天一分钟一次的探测，得到的数字比任何宣传都可靠，也方便和供应商对话。</p>

<h3>排名靠前的就一定适合长期账号吗？</h3>
<p>答：不一定。榜单通常偏向延迟和节点数量，而长期账号更该看可用率、替换政策和出口是否独享。权重换了，名次就会变，按自己的场景重新排。</p>

<h3>售后响应时间怎么提前验证？</h3>
<p>答：售前阶段提一个具体的技术问题，比如「单 IP 支持多少并发会话」「超流量如何计费」，记录回复时间和回答的具体程度。含糊其辞或只回销售话术的，后面大概率也这样。</p>
